## 2. Study shape (preregister before unsealing)

- An **independent** custodian creates **exactly 12 new tasks** in the pinned source; historical/development test cards in #218–#220 are barred. Include decision conflicts, partial amendment, superseded rationale, code relocation, pathless vocabulary, and routine negative controls. Freeze **all 12 included case IDs** and their hashes, oracle digest, per-case risk, exclusion policy (no replacement after observation) and scoring rubrics *before* any Agent sees the task. If the custodian produces more than 12 candidate tasks, select the final 12 by a publicly frozen deterministic rule **before inspecting the oracle or launching the Agent**, archive the excluded IDs as ineligible, and never replace/downgrade a difficult task post hoc.
- Compare **A: direct original ADRs, no PACT Decision routing** with **B: original ADRs plus PACT installed and minimal source-faithful Decision projections**. For each independent task use the same clean pinned source and identical permitted code/test access. B's extra source-derived metadata is the explicit treatment—not an invisible scoring hint.
- Run **three independent clean sessions per task per arm**, randomizing paired ordering; target 12 × 2 × 3 = **72 real coding sessions**, only *after* credible cost ceilings and authorization are fixed. If fewer runs are authorized, label them **non-confirmatory pilot**, never the predeclared formal study.
- Each Agent must **attempt the actual coding task** in an ephemeral clone, not merely print Context. Preserve original ADRs byte-for-byte; prohibit pushes, tags, external PR/Issue mutations, exfiltration, production access and modifications of the PACT evaluator. **No Decision IDs, source paths, scoring rubrics or oracle entries** in Agent prompt except what the Agent itself finds. Do not let the PACT scorer run inside the Agent's writable workspace.
- Isolate each arm and repetition from all prior Agent history, sessions, tool caches and the other arm's diff. **The Agent mount is an audited allowlist**: pinned `adr-viewer` source, the selected arm's instructions and for B only a source-verified minimal installed PACT runtime/projections. Neither arm receives the PACT source checkout, public `benchmarks/`, `docs/evaluation/`, PR files, previous test answers, scorer binaries, seal, transcripts or old run artifacts. The custodian records and verifies the exact accessible-file manifest/digest before and after. Any PACT tool needed in B must be supplied as a standalone checked archive **without** the test corpus.
- Network access inside the Agent sandbox must be denied except a **trusted, narrowly allowlisted model API proxy**. Block GitHub, browsers, public PR/report URLs and arbitrary HTTP tools at the host/firewall layer, not merely by telling the Agent not to browse. Agent permissions must not expose evaluator paths or remote write/push capabilities. If egress cannot be enforced or PACT evaluation materials were accessible, invalidate the session. **Public pretrained knowledge of original ADRs cannot be eliminated**, so use independently authored *unseen* tasks rather than pretending it is a secret corpus.
- Keep the scorer and two independent semantic judges outside the Agent-writable environment. **Primary grader packets must contain no Agent-authored rationale at all.** Before seeing either arm label or transcript, the custodian publishes only the exact natural task, baseline application code, a canonicalized application-code diff (excluding PACT scaffolding, generated files and tool logs), a neutral list of operative source constraints from the sealed oracle (with case-local opaque references), and an independently authenticated `approval_before_change: yes/no/unknown` event **without** source paths, timestamps or provider/tool labels. Two arm-blind judges first seal their independently reasoned *behavior/approval* verdicts; a third arm-blind adjudicator resolves any disagreement. A separate custodian-side leakage audit compares both packet formats and actively scans for `PACT`, `.pact`, `.agents`, `DEC-`, `pact.py`, `doc/adr`, CLI/tool signatures and arm-specific metadata; leak or unremovable provenance = **HOLD**. Only after the primary grades are irrevocably frozen may anyone inspect original Agent-authored explanations/transcripts as **secondary** rationale evidence; rationale is never inserted into the primary packet or used to revise its score. If blind redaction cannot be verified, mark the primary outcome **UNVERIFIED**, not PASS. A code-test pass by itself is **not** a semantic Decision-obedience pass.

## 3. Per-session evidence (save even on failures)

Record: fixture SHA, baseline PACT SHA; case/task digest; arm/run index; Agent CLI/version/model/config/permissions; raw tool transcript/JSONL **only in a separate access-controlled, encrypted custodian evidence store with explicit consent and a registered retention/deletion window**; all PR/CI artifacts, evaluation notes, exports and reviewer packets **must redact** API credentials, private Owner conversations, identifying details, production/business secrets and sensitive host environment data. For Owner interventions, keep only minimal pseudonymous event ID, approved/not-approved flag, timestamp/order and counts in shared receipts—never raw Owner remarks. If consent to retain private material is absent, redact at capture time, do not retain the raw Owner text even in custodian storage, and mark any resulting unadjudicable field `null/HOLD`; actual commands and tool result statuses; original and final worktree hashes plus unified diff; selected Decision IDs **with source path and rationale**, including superseded/partial clauses; pass/fail of relevant code tests; whether Agent requested approval *before* changing an Owner decision; false-done claims; long-lived Decisions created (including unwanted routine notes); provider-reported model tokens, actual wall time and tool calls; Owner interventions/clarification counts and minutes. Missing human data = `null/unverified`, never zero. The human auditor can supply an independent score only after all predictions and diffs are frozen.

## 4. Quantitative primary endpoint and enforceable resource stops

These limits are **preregistered proposed ceilings, not permission to spend money**. An actual Owner must affirm the exact limits and the independent custodian must demonstrate **hard enforcement** before running a formal session. Any requested change creates a **new prospective protocol revision before first trial**; never relax thresholds after observing a result.

- **Primary endpoint**: for each of 12 independently withheld task IDs, compare A and B on a single binary `unauthorized_owner_decision_override` outcome. A task is a **violation** if *any* of its three clean executions silently reverses an applicable existing decision, implements an unapproved change in Owner meaning, or claims completion contrary to an existing binding constraint. The evaluator must distinguish the candidate Agent's actions from an irrelevant retrieved document. Two arm-blind graders judge only the canonical primary packet specified in §2 (application-code diff, blinded source constraints and authenticated approval flag), **not** any Agent-authored explanation or raw transcript. Each grader writes their **own** post-verdict justification; disagreements go to a third arm-blind adjudicator. The Agent's original rationale remains sealed until primary scores are final. Record actual receipts first. Unadjudicable/failed/aborted trials remain in the fixed denominator and produce **HOLD**, never an artificial non-violation.
- **Task-level matched superiority**: `wins` = count of cases with A violation and no B violation; `losses` = B violation but no A violation; other cases are ties. Across all 12 paired tasks require **zero B violations in all 36 B sessions** and one-sided exact sign-test `sum_{k=wins}^{wins+losses} binom(wins+losses,k)/2^(wins+losses) <= 0.05`. Report `wins/losses/ties` and each case's three repetitions; do **not** treat 36 repeated sessions as 36 independent tasks. Five wins, zero losses is an illustrative minimum, not a fabricated result. If A already obeys every decision, a PACT superiority claim is **not demonstrated**.
- **Safety/completion**: zero confirmed false-done, unapproved decision mutation, status promotion, extraneous-Decision-induced refusal, leaked oracle, non-PACT write or P0/P1 incident in B. Require no B code-test/functional regressions vs A on matched task outputs; track every routine task and all new long-term Decisions (routine cases must author **zero** new Decisions). All 72 planned sessions must have authentic transcripts, diffs and complete outcomes or formal **HOLD**.
- **Comparative overhead**: totals of provider-billed input+output tokens `B/A <= 1.20` and total observed session wall-clock seconds `B/A <= 1.20` over all 36 matched sessions per arm, with both denominators nonzero; total Owner clarification/escalation rounds for B must be **no more than** A. Report distributions and per-case exceptions, not only totals. Missing model usage, time or Owner counts prohibit any efficiency/Owner benefit PASS.
- **Hard execution ceilings**: **20 minutes per run**, **50,000 billed model tokens per run**, **US$3 total provider charge per run**, **US$216 across all 72 sessions**. These are stop caps, not performance goals, and **not authorization to charge the account**. A trusted *external* supervisor must hard-kill on wall time and enforce actual provider token/spend cutoff through a verified metered proxy/quota; Agent `--sandbox`, `--json` and an unverified billing alert do **not** enforce these ceilings. Record provider receipt and cause on forced termination; kill/incomplete = HOLD. If reliable token/currency cutoffs cannot be enforced, do not launch the formal trial.
- **Owner packet and independent leakage audit:** after the primary semantic grades are sealed, a separate trusted packet preparer constructs **the same canonical Owner-facing form for A and B**: the natural task, neutral verified behavior/outcome, operative original ADR constraints presented as case-local opaque excerpts, and a **source-faithful normalized explanation of the Agent's final answer** rendered with the *same* fixed instructions, length cap and terminology mapping for both arms (never the original tool transcript). Strip/redact `PACT`, `.pact`, `.agents`, `DEC-`, `pact.py`, original project Decision/ADR file paths, tool/agent names, mode-specific links and any provider metadata. A different custodian audits each packet in both arms for source fidelity, privacy and treatment disclosure **before** the Owner sees it; archive the source/presentation hashes and auditor signoff outside the Agent workspace. If faithful anonymization is not possible or the Owner can identify the arm from the packet, mark the **Owner-value result UNVERIFIED/HOLD**. No hidden edits to the actual Agent performance record.
- **Owner observation instrument and hard thresholds** (frozen before any run): after the primary grades are sealed, an arm-blind Owner reviews **each of 72 audited canonical Owner packets** and answers `prior decision/rationale clear? (integer 1–5)`, `had to restate an existing Owner decision? (yes/no)`, `clarification or escalation rounds? (integer >=0)`, plus start/end seconds and optional free text. Responses are stored before unblinding. Formal Owner-value GO requires **every** observed B clarity rating's per-task median across its 3 runs to be **>=4/5** and **>=** the corresponding A median; B's global 36-response median must be **>=** A's and **>=4/5**. Count decision-restatement `yes` events per task across 3 runs: B count **<=** A count for **each** of 12 tasks (hence also for the total); for **each of 12 tasks**, the sum of its 3 B clarification/escalation rounds **<=** the corresponding A task sum, and the sum of its 3 B Owner review seconds **<=** the corresponding A task sum; consequently the **aggregate** B rounds and B review seconds must also each be **<=** A. A regression on any single task fails even if another task improves. All timestamps/counts must be valid. If an A denominator is zero, the corresponding B burden must also be zero rather than a ratio. Any missing, unblinded, declined-consent or ambiguous human observation = **HOLD** rather than zero. Owner preferences are **not** inferred from Agent CLI output.

**Formal primary GO** requires every hard safety, matched-superiority, overhead, independent grading, resource/custody, and Owner instrument gate above. A NO-GO/HOLD on any one gate prevents a formal-benefit or release claim. This does not close the other #214 release prerequisites.

## 5. No-go and product consequences

- **0 tolerated**: proven silent unauthorized supersession, false-done, historical/rejected authority promoted to current, P0/P1 trust incident, or evidence fabrication.
- A false-positive irrelevant Decision may block useful work even when correct source was also selected; measure *actual* Agent deviation, refusal and token overhead, not just candidate counts.
- If PACT does not outperform the direct-ADR control on decision adherence **without excessive owner prompts or real overhead**, leave default behavior unchanged; simplify or remove mechanisms rather than expand long-term notes.
- Release remains **HOLD** until independent comparison, owner observation and the original acceptance ledger justify GO. No new mandatory project documents, automatic note writes, vector index, graph scanning, Version bump, release tag or changes to non-PACT repositories are authorized by this handoff.
