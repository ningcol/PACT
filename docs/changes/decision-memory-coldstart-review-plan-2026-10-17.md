# 计划盲审材料

## 审查委托（给新会话独立审查者）

你第一次接触下面这份技术计划。**只能依据本文件内的计划内容**作初始判断，不得假定自己知道提出者此前的对话、偏好、评审意见、已讨论结论或任何隐藏项目背景。

请站在苛刻的架构审查者、故障注入测试人员和维护成本评估者立场，开展**对抗性 Review**。你的目的不是证明计划正确，而是尝试推翻它。允许建议取消整阶段、删去新功能、替换实现路线，甚至判断项目现阶段根本不需要这些改动。

严格按如下顺序输出：

1. 用你自己的话概括这份计划试图解决的核心问题。若存在多种解释，指出歧义。
2. 给出是否建议按原样实施的明确结论（GO / CONDITIONAL GO / NO-GO）。
3. 按 P0/P1/P2 列出问题。每条包含：计划章节、造成问题的具体机制、现实失败场景、最小修复建议、可验证的测试方式。**不要凑数量。**
4. 列出计划中的未经证明假设，特别是“自动召回”“防止漂移”“低成本”“兼容性”“不增加长期记忆”等承诺。
5. 提出一个明显更简化的替代方案。如果无法更简单，解释原因，而不是预设原方案最优。
6. 给出不可省略的负面用例：重要旧决策漏召回、已过时决策误阻断、Owner 权限伪造、部分取代信息丢失、任务范围扩大、误增长期文档、已安装项目行为不一致等。
7. 明确列出通过实施前设计审查的必要条件，最多十项；指出哪些必须先以真实源码和安装版行为验证。
8. 区分你实际验证到的事实、从计划推断的风险、纯假设。只做了文档逻辑审查时，严禁宣称已完成源码或 CI Review。

**独立性边界：** 初始评审不得使用本次委托之外的任何对话记录、历史评语或项目记忆；不得从作者意图出发护航方案。若后续要查实际代码，应作为单独的“源码核验”阶段，由审查者自行从仓库 `ningcol/PACT` 的指定基准 SHA 获取只读材料，再用证据核实或推翻第一轮判断；不可将先前其他评审意见注入该阶段。禁止修改 PACT 或其他任何仓库；这里只要求评审计划，不要求实施。

# PACT 决策记忆与抗漂移专项优化计划

**仓库：** `ningcol/PACT`（只允许该仓库的后续实施，不允许更改其他仓库）  
**评审基准 SHA：** `b0eccb0b6315cf22cf8fdc19fad57ff901ba1160`  
**状态：** 设计方案，未实施。  
**设计取向：** 最小改动、默认兼容、长期知识少而精、机器事实与语义判断分离。

## 1. 问题与成功定义

同一项目里，新的 AI 编程 Agent 可能不知道前序会话里做过的重要选择，重新建议曾经否决的方案，擅自改动原有产品/技术约束，并让负责人重复解释。同时，直接保存每次聊天、任务和操作记录会使长期记忆不断膨胀。

计划希望形成：选择性捕获重要决定 → 在新任务中找到相关记录 → 恢复原始理由、有效前提和否决依据 → 在已有约束内完成工作 → 对改变/遗漏进行适当复核 → 对无价值长期记忆做审查而非自动删除。

主要目标：
- 不依赖旧聊天，也能恢复重要且难以从代码/测试中推导的决策理由。
- 不能默默把已确认的产品规则或当前有效的重要技术决策当作不存在。
- 确有新证据、新条件时仍允许合法调整；不把历史否决等同于永久禁令。
- 无关任务不承担大量额外检索、人工批准或新长期文档负担。
- 在未能机器证明语义相关性时，给出候选/不确定性而非伪造结论。

不做：向量数据库、常驻服务、另一份全局知识权威、所有任务强制新建 Decision、自动读取整份历史、根据代码成功自动认定 Owner 批准、自动删除/归档决策、修改其他仓库。

## 2. 权威和技术约束

知识仍分属原有位置：
- Product Truth：用户行为、业务含义、权限、规则，按产品决策权管理。
- Decision：长期工程选择及难以重建的理由、权衡、否决历史；普通技术选择可由 Agent 自主作出。
- Architecture：当前系统结构，必须与现行实现协调。
- Task/Change：一次任务的意图、计划与过程；不默认进入长期决策记忆。
- Evidence：真实运行的检查，不自动转化为产品语义批准。

`implemented` 不代表 Owner 批准，`rejected` 不代表永远禁止，`superseded` 不代表旧记录中所有约束均失效。产品意义、重大风险等需要按已有 Decision Authority 走有权者确认。

当前使用封闭的 Context Envelope v1 和 Task Contract v1。优先复用其已有字段和任务局部状态，不能悄然添加被旧读取器拒绝的 JSON 字段。已安装 compact `pact.pyz`、升级行为、Agent Guide、跨平台 CI 必须一起检查。

机器可直接检查的条件是 ID、路径、显式链接、状态、哈希、有限的关系图一致性；自然语言的“是否违反决定”只能提出有证据的疑点，不能仅凭词语匹配强制判错。

## 3. M0：冻结问题基线

在 PACT 自有临时项目内准备不可在调参后偷偷替换的测试场景：当前有效的长远决策；有理由的否决；完整和部分取代；标题与新任务词汇不同；无关决策；缺少路径元数据；取代环/断链；任务修改受约束代码却未显式给出 Decision ID；普通 Bug 修复无需增加记忆。

先运行原始实现，保留全部实际输出、索引、召回/误召回、Context 预算和失败信息。用实际差异区分确定性可实现缺口、模型理解能力缺口和单纯作者猜测。不伪造历史 RED，也不将作者构造样本称为独立盲测。

门槛：修改前有可重现的反例和兼容性基线，明确什么情况下系统只能报告“未发现”，而非“没有决策”。

## 4. M1：最小决策捕获与精简

仅当未来会重复遇到、遗漏理由可能导致重蹈覆辙、该理由难以从其他权威文档恢复、且不存在重复权威记录时，才建议新增 Decision。否则归于代码、测试、普通架构说明、一次性 Task 或 Change。

每条长期 Decision 以四点为核心：选了什么、为什么选、真实否决了什么及为什么、什么条件下重新讨论。可以附必要的验证方法与准确来源引用，不要求编造不存在的讨论或保存原始聊天。

Owner 确定的长期产品行为应记录于 Product Truth；工程取舍记录在 Decision；不得从普通闲聊、已通过测试或已实施状态推定永久 Owner 许可。普通任务没有新的长期决策时不生成文件。

同步更新 PACT 自身和新安装项目的 Agent 指导，包括 `AGENTS.md`、`scripts/pact/init.py` 的 `TARGET_AGENTS` 和 `bootstrap_snippet()`，并保留已存在的外部项目 Agent Guide（只能提供合并建议，禁止覆盖）。

验收：日常重构/格式化/普通修复不产生强制新增长期记录；需持久记录的决策足以恢复理由，且没有重复事实来源。

## 5. M2：结构化关联和渐进式召回

当前 Project Map 提取 ID、title、status、domains、aliases、paths、related 等；计划补全 `supersedes`、`superseded_by` 的索引与校验，使其可用于从当前 Decision 找到必要的历史依据。必须同步处理 Map 格式版本、逐文件解析缓存版本及已安装 runtime 升级后的缓存重建，避免“代码已支持但旧索引仍缺字段”。

检索候选分三类：
1. **确定性**：显式 ID、精确标题/别名、规范化且边界明确的文件/目录 paths、显式 related/supersedes 关系。
2. **启发式**：任务词汇、业务同义表达、现有词法/多查询/代码关系候选，不能把相关猜测提升为权威。
3. **历史按需展开**：只对影响任务的现行 Decision 读取必要的旧理由、取代链和否决信息，不将历史正文全量注入。

初始展示目标可为 1–3 条高度相关 Decision，但不得作为硬正确性上限；明确强相关的记录若超预算，应报告截断及其影响。区分“已选入”“候选未选”“预算截断”“未发现”“充分性未知”。没有找到不等于不存在。

路径规则以仓库相对路径和目录段边界为主，拒绝 `..`、绝对越界、符号链接逃逸及无界正则/Glob 作为第一版默认索引。完整/部分取代关系中的 ID、引用、自引用、循环、方向一致性要分出确定性错误与向后兼容的历史不完整元数据；机器不从自由文本判断某项旧约束是否已失效。

保持默认无 `--intent` 检索的已有契约；优先试验可选有界增强，必要的元数据迁移必须先通过 Schema、源运行时和 compact 安装版的兼容性用例。

验收：显式关系可检索，新的相关任务用语有可量化召回改善或明确不改善；无关任务不大量读取 Decision；历史否决/归档不当作当前规范；缓存无虚假新鲜命中。

## 6. M3：任务局部决策绑定与漂移复核

研究增加可选 `--require-decision DEC-*`，模仿已有显式 `--require-rule` 的失败关闭。仅用于已知 ID 的当前重要 Decision，不作为所有任务必需参数；找不到的 ID、非 Decision 类型、历史状态、未选入 Task Context 或无法明确的取代继承必须显式告警/失败。不能把此命令当作未知 Decision 发现机制。

`task prepare` 对明确必需/结构化关联的相关决策记录最小任务局部绑定：ID、路径、准备时 SHA、来源以及显式要求还是自动候选。这是任务证据而不是新长期记忆；优先使用兼容的局部 Manifest、不可未经协议设计改变封闭 Context v1 与 Contract v1，不能宣称本地 JSON 防篡改。

`task finish` 重新核对：显式 Decision 是否存在/有效、准备时绑定的正文是否发生变化、选中 Decision 是否获得 Convergence Coverage、任务最终改变的文件是否触及其他有明确 `paths` 关联的当前决策、是否需要重新准备 Context。

与任务准备时相比，已绑定 Decision 被删/被改不可通过简单的 `aligned` 或 `not-applicable` 悄然略过；合法格式/链接维护与有实际语义变化的取代应区别处理。部分取代须保留依然有效的旧约束；变更产品含义/权限/重大风险交由有权 Owner 判定。技术实现细节由 Agent 自主裁决，避免反复打扰。

对未在 Context 中但与改动文件存在明确结构化关联的现行决策，至少如实报告遗漏；对于启发式相似项，先做非阻断提示而非无证据硬阻断。准备后任务范围扩张时，不可静默改写被冻结的 Context，应使用现有重新准备与证据失效机制。

自动发现产生的任何**新增阻断门禁**必须先在可选/实验模式下证明误报率可接受，而不是直接默认阻断一切相关技术修改。

验收负例：要求 Decision 缺失、旧 Decision 正文被悄改却标记 aligned、决策文件被删除却伪装成合理 removed、取代链损坏、最终改动文件与未选 Context 的现行 Decision 有明确关联、历史记录错误升格、普通无关修改误拦、合法工程重构被误要求 Owner 批准。仅对机器能证明的事实失败关闭。

## 7. M4：长期记忆清理候选而非自动清理

复用 `audit` 与现有 Knowledge Gardening，提示重复长期理由、完全取代但仍被当作现行的记录、仅保存任务流水的记录、可由权威代码/测试重新恢复的重复解释、失效的历史链接。候选审查不得自动删除、合并、修改决策状态或仅因年龄/文件大小/反向引用少就归档。

优先在同一权威位置保留精简理由与显式引用；历史理由按需展开。用任务实际加载 Decision 数、估算 Token、无意义新增文件数、重复率、旧理由可找回性及遗失率评估，而非只追求文件总数减少。

验收：普通任务没有“为了符合流程”创建的 Decision；任何精简后都能回溯重要理由，未出现新的自动删除风险。

## 8. M5：跨会话及效果验证

**工程用例**：PACT 临时安装环境中无 Decision ID 的任务、表达差异、历史否决、部分取代、路径触发、真实改动、无关任务以及旧 compact 安装/升级回归。全部记录失败、具体 SHA 和实际日志。

**真实效果**：从零启动没有旧聊天上下文的新 Agent，设置预先冻结的案例和评分规则，比较不使用与使用 PACT 的条件；衡量旧决策召回、理由解释准确性、重复提出旧否决方案的次数、未经授权改变约束次数、Owner 不必要澄清次数、无意义 Decision 新增、检索 Token 与时间开销。独立盲测样本不可由实现者按测试反馈反复调整。

将“工程门禁通过”和“真正减少 Agent/Owner 决策拉扯”分成两个验收状态；没有授权 Agent 会话和真实人的判断时，只能标记效果未验证。不得通过修改其他用户项目补造试点数据。

- PR2：M1 准入/最小记录和安装后 Agent Guide。
- PR3：M2 结构化决策关系、代码路径、索引缓存升级和检索。

每个阶段需三种审查：决策权限和语义；完整调用链与对抗负例；默认行为/compact 安装/跨平台性能与兼容。发现实际错误时修后复测；三轮由同一审查者执行不得称为三个独立评审者。

持续运行当前 PACT Check 与真实 fail-fast 的 Linux/macOS/Windows × Python 3.11–3.13 九组合测试；涉及安装后行为必须检查真实打包的 `pact.pyz`，不能仅检验源码导入。

## 10. 工程完成条件

- 决策首次保存有权限、来源和高价值门槛，不制造新的“全部任务纪要”知识库。
- 无聊天记忆的新任务能通过可靠的显式结构化关联找出相关现行决策；启发式未覆盖部分如实注明。
- 已知必须保留的当前 Decision 不能因检索缺失或预算截断静默通过。
- 准备时绑定的决策在执行后被修改或删除必须有可验证的变化处理；不能仅靠填写 `aligned` 或 `not-applicable` 掩盖。
- 任务已知影响的代码文件与当前 Decision 显式 `paths` 关系得到有界核对，不把自然语言关联猜测伪装为确定性违规。
- 旧方案否决理由和部分取代的仍有效约束可找回；旧历史不会错误提升为新的永久产品规则。
- 普通无关任务不被强制新建文档、审批或付出不合理检索成本。
- Context v1、Task Contract v1、安装和升级、现有旧任务、跨平台与 PACT Check 不退化。
- 工程结案不声称真实 Agent/Owner 效果已经得到独立验证；正式发布仍依赖单独发布门槛。
